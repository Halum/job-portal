# JSearch switches API keys on quota refusals and fails the run when all are out

Partly superseded by [0027](0027-jsearch-source-rotates-over-api-and-key-slots-and-logs-every-request.md): the current key is no longer kept in memory, each search rotates over the slots of its pool with the position read from the request log, and `JSEARCH_API_KEYS` is now `OPENWEBNINJA_API_KEYS`. The refusal handling and the keys-exhausted failure below still hold.

Issue #32, spec #28. The `jsearch` Source takes a list of API keys (`JSEARCH_API_KEYS`, secrets from env only) so that one key running out of quota does not stop the search. How often it runs is only the interval in config, so a paid plan needs no code change, and there is no request cap or budget logic.

An HTTP 429, 401 or 403 marks the current key unusable and the same request is retried with the next key. The unusable set is cleared at the start of each fetch, so a key that recovered is tried again on the next run. The index of the current key is kept in memory between runs until the worker restarts, so later requests start on the last working key instead of retrying an exhausted one first. When every key has been refused on one request, the Source throws a keys-exhausted error that the per-query catch rethrows: the run stops at once and fails. The Pipeline opens the existing failure type `source:jsearch` (one alert) and the first run that works again closes it (one recovery alert). Any other failure of one search is an error line `search <n> failed: HTTP <status>`, numbered by position and never carrying the query text. The run keeps the other searches and fails only when every search failed.

No error line, log line or thrown message contains a key. Keys are named by position (the smoke run prints the key position it ended on, counted from 1), and any other error text is scrubbed of every configured key before it becomes a line.

Discovery never calls Matching: the Source takes `queries` and the worker wires it to Matching's `textQueries`, the keyword and location pairs of the active Targets (saved Bundesagentur URLs never included, radius only with a location, deduped, at most `MAX_QUERIES`). Each query runs once per configured publisher with ` via <publisher>` appended. `JSEARCH_PUBLISHERS=any` means one search without a publisher, and an empty value is a ConfigError. The Source is built and scheduled only when both an interval and at least one key are set.
