# Targets replace the env search, and Matching is its own module

This supersedes the stopgap in ADR 0002. The Bundesagentur search no longer comes from `BUNDESAGENTUR_QUERY` (removed): the source takes a `queries` function and the worker feeds it from `matching.searchQueries`, one request per active Target, keyword and location (a Target with neither keyword nor location is skipped, so nothing fetches the whole country). Searches that fail are error lines on the run and only a run where every search failed fails; postings found by several searches are stored once. `BUNDESAGENTUR_INTERVAL_MINUTES` stays, as optional config like bambase's: the source is scheduled only when it is set, and it has no default any more. The old fixed `query` option stays on the source for tests.

Matching is a package with schema `matching`: Global defaults (one jsonb row per user), Targets (unique per user and name, paused flag, jsonb criteria) and `candidates` (the Jobs that passed a Target's hard filters and prerank, with the score and an unknown-location flag). Criteria are one zod schema with every field nullable: null means unset and inherits, so 0 and false are real values. Resolution is a pure function (a set Target field replaces the Global one, exclusion words and blocked companies are unioned). Edits are patches (a missing key keeps the value, null clears it) under a row lock, so two concurrent edits both land.

Matching reads Jobs only through an injected `loadJobs` (Discovery's `listMatchable`, which leaves out Dismissed and Expired Jobs) and skips Jobs for which an injected `hasApplication` says they have an application status; the Tracker wires that hook. `list_jobs` by Target is `candidates` handed to Discovery as a `jobIds` restriction that applies before the limit and cursor. A Posting stored for the first time puts its Job in the run's `jobIds`; Matching runs over those only, after the poll, and a failure there is an error line on the run, not a failed run. `runs.prerank_passed` counts the passes.

Hard filters: exclusion words and blocked companies match as case-insensitive whole words (letters and digits count as part of a word, so "Pflege" does not hit "Pflegedienst"); remote postings (title or place says remote, home office) skip the radius and pass unless the Target sets remoteAllowed false; a radius check needs both a Target location and a radius, so null radius means no place filter and 0 means the same city (equal normalized name) only; an unknown place passes with the unknown-location flag. The salary floor is stored and resolved but not applied, because no Source reports salary yet. Prerank scores a keyword 3 in the title and 1 elsewhere in the payload, passes the top `prerankTopN` (Target, then Global default, then `PRERANK_TOP_N`, default 20), and with keywords never passes a score of 0.

The place table is the GeoNames postal code file for Germany (CC BY 4.0, 23k rows, credit in `packages/matching/data/NOTICE.md`), read once at first use. A name shared by several states resolves to the average of them; a postcode shared by several villages resolves to its first listed place.
