# The AI runner is its own module, and fit scores live in Matching

The AI runner is a package with schema `ai`: one interface (`AiRunner.complete(prompt)`, a prompt in, text, tokens and reported cost out, or an `AiError` with a class) and two implementations. OpenRouter is plain HTTP (`fetch`, no SDK); `claude -p` is a child process that gets the prompt on stdin, never in the argument list, with the model and effort as flags, no tools and no saved session. The runner is chosen by `AI_RUNNER` and there is no fallback to the other one; unset means nothing is scored. The OpenRouter key is env only. `createAi(log, runner).run` wraps a call: it parses the answer with the caller's parser, writes one row to `ai.calls` (runner, model, feature, tokens, cost where reported, duration, outcome, error class; never the prompt or the answer) and throws the `AiError` after logging it. A paid answer the parser rejects is logged as a `bad_output` failure and keeps its tokens and cost. A cost of 0 is a real cost and null is unknown; totals sum the reported ones. `get_run_history` shows the totals over the whole log (`aiTotals`) and each Run carries its own scored, tagged, AI call and cost counts.

Scoring is in Matching, in a table of its own (`matching.scores`, unique per Target and Job), not on `candidates`: editing a Target replaces its candidates, and a score must survive that. A candidate with no score row is unscored. The model only extracts (a 0 to 100 score, short reasons and red flags, and the languages the posting demands with a CEFR level); whether the Target can meet a language is judged in code against its `languageAbility` entries such as `de:B2`. An unmet required language caps the score at 20 and adds a red flag; a required language with no level named counts as B2; a Target with no ability set is not judged (`languageMet` null). Below the threshold the score is stored and nothing else happens (the Review item for it is a later ticket). The threshold is the Target's, then the Global default, then `ALERT_THRESHOLD` (default 70), and 0 is a real threshold. The tag is fixed when the pair is scored; a later threshold edit does not retag.

Every Run scores every unscored candidate of the user, oldest first, not only its own Jobs, so a pair whose call failed is retried by the next Run of any source. A failed call leaves the pair unscored and is an error line with its class, so the Run ends completed with errors; a pass stops after three failures in a row so a dead runner does not burn calls. Several workers share the database: a pass takes each candidate row with `FOR UPDATE SKIP LOCKED` in a transaction that stays open through the AI call (the database releases the lock if the worker dies), and looks for a committed score again once it holds the lock, because the lock alone does not see a score committed after the query began. The unique key is the last guard. One connection is held per call in flight.

`list_jobs` takes `minScore` with `targetId`, applied in the same query path as the other Target filter, before the limit and cursor; unscored Jobs never match it, not even at 0. `get_job` lists each Target the Job is a candidate for with its score, reasons, red flags, extracted languages, language verdict, tag and the unknown-location flag.
